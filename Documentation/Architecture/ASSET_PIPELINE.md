# Phase 2 – Blender Asset Pipeline

All jewellery is generated by version-controlled Python scripts run in headless Blender 5.3.
The live Blender MCP add-on was not running during development. The scripts don't need it, and every asset
can be rebuilt from scratch with one command.

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python Blender/Scripts/build_all.py -- --samples 64
```

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python Blender/Scripts/export_web.py
```

```bash
python3 Blender/Scripts/sync_catalogue.py
```

`--no-render` skips the Cycles previews (about 3 s without renders, about 5 min with). `--only solitaire,gems` rebuilds a subset.
`sync_catalogue.py` writes the measured cut depths and mount positions back into the Unity catalogue.

Renders use a transparent film with a shadow-catcher floor and large softboxes, so previews sit cleanly on the dark
interface or any page background. The gem showcase is shot near top-down without an on-axis light, so tables aren't blown out.

## Scripts

| File | Purpose |
|---|---|
| `gx_gems.py` | Faceted gem generator. Each cut is the intersection of facet half-spaces (girdle point + direction + cutting angle), so every facet is exactly planar and the solid is watertight. Output is normalised to a 1 × 1 × 1 bounding box with the girdle centre at the origin |
| `gx_rings.py` | Ring builders: comfort-fit tapered band, claw-prong heads with gallery rails, halo frame with bead-set accent stones, cathedral shoulders, bezel collar. Heads are sized from the default stone's real proportions |
| `gx_common.py` | Mesh builder (mm in, metres out), tube/sphere/sweep primitives, Principled BSDF metal and gem materials driven by the Unity catalogue JSON, FBX/GLB export, studio lighting and Cycles render |
| `build_all.py` | Builds everything, saves `.blend` sources, exports FBX (Unity) and GLB (review), writes `asset_metadata.json`, copies FBX into `Assets/GemXpert/Models` |
| `export_web.py` | Web GLBs (settings without stones + unit cuts) and embedded-glTF JSON for the browser interface preview |

The catalogue JSON in `Assets/GemXpert/Configurations/Resources/Catalogue` is the single source of truth: ring sizes,
default stones, metal colours, gem colours and refractive indices are all read from it.

## Simulated hand (`gx_hand.py`, `--only hand`)

A realistic adult **left** hand, palm down, for trying rings on, and the Phase 4 fallback hand when no
headset hand tracking is available.

* **Anatomy:** four fingers and a thumb, each lofted through three phalanges with flatter dorsal and fuller palmar
  cross-sections, knuckle bulges at the PIP/DIP joints and fingertip pads. Also MCP knuckles, extensor tendons,
  thenar and hypothenar muscles, palm pads and a wrist stub. Proportions follow average adult measurements.
* **Organic surface:** all parts are fused with a 0.55 mm voxel remesh, smoothed, then decimated to 48k triangles.
* **Skin:** baked vertex colours (warmer over joints, knuckles and fingertips, paler on the back of the hand, pinker on
  the palm, faint mottling). The Blender material adds subsurface scattering; the web viewer uses a sheen material.
* **Nails:** separate glossy meshes (3.1k triangles) ray-cast onto the skin. Oval free edge, rounded cuticle,
  lunula and pale tip, with edges set into the skin folds.
* **Ring fit:** the ring finger is 16.6 mm wide at the ring position, shaped so a 17.3 mm band rests on its back.
  `RingAnchor_RingFinger` (identity rotation) is where a ring's origin goes: band along the finger, stone on the
  back of the hand.
* **Outputs:** `Exports/FBX/Hands/SimulatedHand_L.fbx` (copied to `Assets/GemXpert/Models/Hands`), web GLB/JSON,
  `Renders/Hand_RingOnFinger*.png`, `Source/Hands/SimulatedHand_L.blend`.
* **Not included:** the hand is a static pose with no rig. Phase 4 drives the VR hand from XR Hands joint data, and
  rigging this mesh to those joints is part of that work.

## Hierarchy contract (used by Unity)

```
Ring_<Design>            root, origin = band centre
  Band                   metal
  Cathedral              metal (prong design)
  GemMount_Center        girdle centre of the centre stone; +Y (Unity) out of the table
    Head_Center          metal, scaled in X/Z to follow the chosen stone's footprint
    Halo_Frame, Accent_NN
    Bezel
  GemMount_SideL/SideR   three-stone side mounts (+ Head_SideL/R)
```

The setting FBX contains **no centre stone**. Unity instantiates `Gem_<Cut>.fbx` (1 mm unit cut) under the mount and
scales it to `(width, depth, length)` in millimetres. Measured mount positions are written back into `rings.json`
(`fallbackPositionMm`) and real cut depths into `shapes.json` (`depthRatio`).

## Export settings and axes

FBX: metres, *Apply Scalings = FBX All*, forward −Z, up Y, *Apply Transform* on. Blender −Y → Unity +Z (finger direction),
Blender +Z → Unity +Y, Blender +X → Unity −X. That's why Unity's `SideL` (x < 0) is built at Blender +X.

## Known limitations / still to verify

* **Not yet imported into Unity** (the Editor isn't installed). Scale, axis conversion of the tilted side mounts and material
  slot names must be checked on first import.
* Real-time Unity materials are authored separately in Phase 3. Blender's transmission shader does not carry over through FBX.
* The princess has 45 facets (commercial princess cuts have about 50–76). Add tiers in `PRINCESS_TIERS` for more.
* Heads are modelled for the default stone and scaled for other sizes and cuts. Cut-specific prong layouts (e.g. a V-prong at a pear tip) are future work.
