## Blender

| Item | Status |
|---|---|
| Blender | **5.3.0** at `/Applications/Blender.app` |
| Blender MCP – live add-on connection | **Not reachable** (nothing listening on `localhost:9876`; Blender not running with the MCP add-on server started) |
| Blender MCP – background/CLI tool | **Not usable as configured** – it looks for an executable named `blender` on PATH and fails (`BLENDER_PATH` not set) |
| Headless Blender via shell | **Works** – `/Applications/Blender.app/Contents/MacOS/Blender --background --python <script>` was used successfully to create a test `.blend` |

Decision: jewellery assets are generated by **version-controlled Blender Python scripts** run headlessly
(`Blender/Scripts/*.py`). This is reproducible, reviewable and does not depend on the live add-on.
When the live add-on is running, it is used additionally for visual inspection/screenshots.

To enable the live connection: open Blender → enable the MCP add-on → start its server (port 9876).
To fix the CLI tool: set `BLENDER_PATH=/Applications/Blender.app/Contents/MacOS/Blender` in the MCP server's environment.

## Headset

**No VR headset is available.** Consequences:

* The application must be fully usable without a headset: a **Desktop Preview** run mode (mouse + keyboard
  driving the same world-space VR UI) and the **XR Interaction Toolkit Device Simulator** (simulated
  HMD, controllers and hands) are first-class run modes, not afterthoughts.
* OpenXR is configured for the Android/Meta Quest target so the project is headset-ready, but
  **nothing headset-specific can be tested on this machine**. Each such item is listed in
  `Documentation/Testing/HARDWARE_TESTS_REMAINING.md` (created as phases progress).
* Note: OpenXR has **no runtime on macOS**, and Meta Quest Link does not run on macOS. Even with a Quest,
  on this Mac you would test by building an APK and installing it over USB.

## Missing dependencies (summary)

1. Unity 6 LTS Editor – **user installs through Unity Hub** (requires Unity account sign-in + free Personal licence activation, which only the user can do).
2. Unity packages (URP, Input System, XR Management, OpenXR, XR Interaction Toolkit, XR Hands) – installed automatically by `GemXpert ▸ Setup ▸ Run Full Setup` inside Unity.
3. Python `bleak` – only for the desktop BLE bridge in Phase 5.
4. ESP32 + MPU6050 hardware – Phase 5; a mock sensor simulator covers its absence.
